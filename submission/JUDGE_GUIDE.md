# FriendOS — Judge Guide

## The pitch

**Your Rare Friend can think, work, and spend.**

FriendOS turns a Generations NFT into a persistent AI operator. Each Friend has a distinct identity, wallet view, spending policy, installed skills, mastery, mission history, and reputation. Assign useful work, receive a task-specific result, and see exactly how the simulated RF fee moves through burn, compute, and ecosystem or skill-creator allocations.

## Recommended 90-second walkthrough

### 0:00–0:12 — Establish the character

Open the public demo without connecting a wallet. Point to Signal and switch between the three guest operators.

Say: “The NFT is not decoration beside an assistant. Each token is the operator, and switching tokens changes its identity, budget, skills, progression, and history.”

### 0:12–0:25 — Inspect capability

Click **What can Signal do?** Show the native traits, installed skills, and mastery. Explain that this list updates when a skill is installed.

### 0:25–0:50 — Complete useful work

Choose **Social Content**, use the suggested launch brief, and click **Launch mission**. Continue navigating while the compact mission panel runs. When complete, open the result.

Point out that social feedback is structurally different from blockchain analytics, quick answers, strategy, and deep investigations.

### 0:50–1:07 — Prove token activity

Read the receipt: RF spent, RF burned, compute allocation, ecosystem or creator allocation, skill used, XP, and CRED. Return to the workspace and show that the mission is now attached to Signal’s history.

### 1:07–1:22 — Prove economy potential

Open **Skills**. Select a paid skill and show that FriendOS asks which operator should receive it. Explain that an approved community skill receives 20% of matching usage fees when it is installed and used.

### 1:22–1:30 — Show the expansion path

Open **Train a Skill NFT**. Explain how non-developers can train specialist agents through evidence-backed approvals and public task performance. Finish with: “FriendOS turns collecting a Friend into operating, improving, and economically participating with one.”

## Category proof

### Best use of a Generations NFT as the main character

- The token ID is the state boundary for identity, wallet, spending policy, skills, mastery, missions, XP, CRED, and evolution.
- Connected owners can load up to three owned Generations NFTs through FriendSDK and see canonical sprite data.
- Operator capability visibly changes as skills are installed and relevant work increases mastery.

### Most successful at burning or spending RF

- Every mission consumes an RF-denominated operating budget.
- Every receipt exposes the proposed 50% burn rather than hiding the economic action.
- Skill installation and repeat skill usage add further recurring RF demand.

### Best potential for a token economy paired with RF

- Mission fee proposal: 50% burn, 30% compute/service, 20% ecosystem.
- When a community skill powers a matching mission, its creator receives the final 20% allocation.
- Skill reputation can develop from mastery, accuracy, successful execution, and community-visible task history.
- Training gives non-developers a route to create useful specialist supply.

## Submission form copy

### One-line description

FriendOS turns a Rare Friends Generations NFT into a persistent AI operator that completes useful missions, spends RF, acquires community-built skills, and grows through verifiable work.

### Short description

Choose a Generations Friend, inspect what it can do, and assign a social, analytical, strategic, or research mission. The Friend returns task-specific work plus an economic receipt showing RF spent, burn, compute, creator allocation, XP, and CRED. Every operator preserves its own wallet controls, skills, mastery, progression, and history. FriendSDK powers wallet connection, Robinhood Chain lifecycle, owned-Friend discovery, public reads, and canonical sprite data. The public demo remains fully explorable without a wallet.

### Why it matters to Rare Friends

FriendOS gives every Friend a reason to be used repeatedly. Missions create recurring RF demand, progression makes ownership more personal, and the skill marketplace lets outside developers extend the utility of the collection while earning from actual usage.

## Honest disclosure

RF balances, mission charges, burns, allocations, payouts, and progression are simulated browser state in this Vibeathon build. Connected-wallet RF holdings are read-only. No approval, transfer, or burn transaction is submitted. The static Pages build uses deterministic offline mission results; the included serverless endpoint enables live task-specific AI when configured with an API key.
